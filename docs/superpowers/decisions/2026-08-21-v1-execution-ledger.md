Ruling F-3: Task 9 forks a worker resolved relative to import.meta.url. Under vitest the client runs from src/proc/ as TypeScript, so the sibling query-worker.ts would be forked as a source file whose own `../store/connections.js` specifier has no matching file on disk — type stripping does not rewrite specifiers. Decision: always fork the COMPILED worker. Add `"pretest": "npm run build"` to package.json (Task 1) and resolve WORKER src/dist-aware in Task 9. Cost if wrong: the query-process tests fail to spawn, which surfaces loudly in Task 9 rather than silently.

Ruling F-4: Task 9's `#ensure` assigns `this.#ready = this.#spawn()` and awaits it, but two concurrent `run()` calls can both observe `#child === null` and spawn two children, leaking one. Decision: memoize the in-flight spawn promise so concurrent callers await the same spawn. Cost if wrong: a leaked child process per concurrent burst — invisible in tests, a resource leak in production.

Ruling S-1: The user noted Tasks 14-15 (BLOB decoders) would ideally wait for a real library, arriving tomorrow. Decision: execute them now. Their tests are purely defensive — framing round-trips, garbage handling, per-field status — and require no real bytes. Real-library validation is already a separate checklist at the end of the plan. Cost if wrong: the decoders' field layouts prove incorrect against real data and Task 14's parsing bodies need revision, while the framing, contract and error handling survive.
